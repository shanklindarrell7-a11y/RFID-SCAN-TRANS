# RFID Signal Export Formats

This document describes the various export formats supported by the RFID Sniffer application.

## Supported Export Formats

### 1. Flipper Format (.sub)
**File Extension**: `.sub`  
**Description**: Native Flipper Zero SubGhz format for captured RFID signals.

**Use Case**: Replaying signals directly on Flipper Zero or sharing with other Flipper Zero users.

**Example Output**:
```
Filetype: Flipper SubGhz RAW File
Version: 1
Frequency: 125
Preset: FuriHalSubGhzPresetOok650Async
Protocol: EM4100
RAW_Data: A1B2C3D4E5
RSSI: -45
Timestamp: 1704627600
```

### 2. CSV Database (.csv)
**File Extension**: `.csv`  
**Description**: Comma-separated values format for easy import into spreadsheet applications.

**Use Case**: Data analysis, logging, and database integration.

**Example Output**:
```csv
Timestamp,Protocol,Frequency_kHz,Data_Hex,Data_Length,RSSI_dBm
1704627600,EM4100,125,A1B2C3D4E5,5,-45
1704627605,HID Prox,125,12345678,4,-50
```

**Features**:
- Supports append mode for continuous logging
- Header row for easy data identification
- Compatible with Excel, Google Sheets, etc.

### 3. Wiegand Format (.wiegand)
**File Extension**: `.wiegand`  
**Description**: Industry-standard Wiegand format with facility codes and card numbers.

**Use Case**: Access control systems integration and card duplication.

**Example Output for 26-bit HID**:
```
# Wiegand Format Export
# Protocol: HID Prox
# Frequency: 125 kHz

Format: 26-bit
Facility Code: 123
Card Number: 45678
Hex: 12345678
```

**Example Output for Generic**:
```
# Wiegand Format Export
# Protocol: EM4100
# Frequency: 125 kHz

Bit Length: 40
Binary: 1010000110110010110000111101010011100101
Hex: A1B2C3D4E5
```

### 4. Proxmark3 Script (.pm3)
**File Extension**: `.pm3`  
**Description**: Ready-to-use Proxmark3 command scripts for signal replay and analysis.

**Use Case**: Direct integration with Proxmark3 hardware for advanced RFID operations.

**Example Output**:
```
# Proxmark3 Command Script
# Protocol: EM4100
# Generated by Flipper Zero RFID Sniffer

# EM4100 Read/Clone Commands
lf em 410x_read
lf em 410x_sim A1B2C3D4E5

# Raw data: A1B2C3D4E5
```

**Supported Protocols**:
- EM4100: `lf em 410x_*` commands
- HID Prox: `lf hid *` commands
- Indala: `lf indala *` commands
- Mifare Classic: `hf mf *` commands
- ISO14443A: `hf 14a *` commands

### 5. JSON Metadata (.json)
**File Extension**: `.json`  
**Description**: Structured JSON format with complete signal metadata.

**Use Case**: API integration, web applications, and programmatic access.

**Example Output**:
```json
{
  "protocol": "EM4100",
  "frequency_khz": 125,
  "timestamp": 1704627600,
  "rssi_dbm": -45,
  "data": {
    "hex": "A1B2C3D4E5",
    "length": 5,
    "bytes": [161, 178, 195, 212, 229]
  },
  "metadata": {
    "source": "Flipper Zero RFID Sniffer",
    "version": "1.0"
  }
}
```

**Features**:
- Machine-readable format
- Full metadata preservation
- Easy parsing in any programming language

## Usage

### Exporting a Single Signal

```c
// Example: Export to Flipper format
ExportResult result = export_to_flipper_format(
    storage,
    "/ext/rfid_exports/signal_001.sub",
    RFIDProtocolEM4100,
    &captured_signal
);

if(result.success) {
    FURI_LOG_I(TAG, "Exported %zu bytes successfully", result.bytes_written);
} else {
    FURI_LOG_E(TAG, "Export failed: %s", result.error_message);
}
```

### Batch Export to CSV

```c
// First signal - create new file
export_to_csv_format(storage, "/ext/rfid_exports/log.csv", 
                      protocol, &signal1, false);

// Subsequent signals - append to file
export_to_csv_format(storage, "/ext/rfid_exports/log.csv", 
                      protocol, &signal2, true);
export_to_csv_format(storage, "/ext/rfid_exports/log.csv", 
                      protocol, &signal3, true);
```

## File Organization

Recommended directory structure on SD card:

```
/ext/rfid_exports/
├── flipper/        # .sub files
├── csv/            # .csv database files
├── wiegand/        # .wiegand format files
├── proxmark3/      # .pm3 script files
└── json/           # .json metadata files
```

## Error Handling

All export functions return an `ExportResult` structure:

```c
typedef struct {
    bool success;              // true if export succeeded
    char error_message[128];   // error description if failed
    size_t bytes_written;      // number of bytes written to file
} ExportResult;
```

Common error scenarios:
- File system full
- SD card not inserted
- Invalid file path
- Permission denied
- Corrupted signal data

## Performance Considerations

- **Flipper Format**: Fast, minimal processing
- **CSV Format**: Fast, good for batch operations
- **Wiegand Format**: Moderate, includes bit-level parsing
- **Proxmark3 Format**: Fast, template-based generation
- **JSON Format**: Moderate, includes full serialization

## Compatibility

- **Flipper Zero**: All formats readable by Flipper apps
- **Proxmark3**: .pm3 scripts directly executable
- **Access Control Systems**: .wiegand files compatible with industry standards
- **Data Analysis Tools**: .csv and .json widely supported
